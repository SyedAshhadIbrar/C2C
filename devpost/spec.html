Chaos to Clarity: Technical Spec

React 19 + TypeScript screen, one FastAPI endpoint, Qwen in JSON mode, and two checks between them.

In plain language. The frontend is the screen and holds your plan in memory. The backend is the only place with your API key: it asks Qwen for JSON, then checks it twice. First the schema check (Pydantic: right shape?), then the grounding check (your rules: supported by the notes?). With no key, sample mode returns a saved response, and both checks still run.

Components

Organize Endpoint app/main.py · prd › Organizing Notes
POST /api/organize {notes}. Empty → 400. Runs extract → schema → grounding → OrganizeResponse. AI/schema failure after the retry → 502. GET /api/health → {mode}.
Qwen Extraction Service app/extract.py
openai SDK → dashscope-intl…/compatible-mode/v1, response_format: json_object, temperature: 0. The prompt says: only what's stated; owner/deadline null unless explicit; relative deadlines copied as written; deadline_ambiguous when unclear; source phrase verbatim; questions never answered. Exactly one automatic retry, only for malformed JSON or a Pydantic schema failure. Grounding failures never retry. No key → sample_response.json, mode: "sample".
Schemas (schema check) app/schemas.py · prd › Task Cards
ExtractedTask: id, title, owner?, deadline?, deadline_ambiguous,
               source_phrase, blocked_by[], blocker_note?
OpenQuestion:  text
Extraction:    tasks[], open_questions[]
Rejects missing fields, wrong types, and empty title or source phrase.
Grounding Check app/grounding.py · prd › Verification Warnings
  • Source phrase: normalized phrase ⊂ normalized notes
  • Owner: null, or normalized owner ⊂ normalized source phrase
  • Deadline: null, or normalized deadline ⊂ normalized source phrase. Kept exactly as worded (“by Friday”, “next week”), never reworded or converted to a date. Normalization is only for comparing.
  • Failure → Needs verification warning; the task is never removed, and there is no retry
App Shell + NotesPanel App.tsx · prd › Screens and Layout
All state lives in useState: notes, status (idle/loading/error/done), plan, mode. A two-column grid. Empty notes → "Paste notes first," no request.
ResultsPanel prd › States and Boundaries
EmptyState · loading · error with Retry · results with Add task, Export, and the Sample mode badge. Zero tasks → "No actionable tasks found."
TaskCard prd › Task Cards · Editing · Deleting · Adding
Title → owner/Unassigned → deadline/Deadline not specified + clarify prompt → source quote → blocked by. Inline edits; an edited owner/deadline → user-provided, which clears that flag and warning. The source phrase never changes. Inline "Delete? Yes/No." User-added cards skip grounding.
BlockersSection + OpenQuestions prd › Blockers & Dependencies · Open Questions
Blockers: display-only list of "task ← blocked by." Questions: editable text plus a Resolve toggle (struck through).
Markdown Export exportMarkdown.ts · prd › Exporting the Checklist

Failure modes

Bad JSON / wrong shape

One automatic retry → error with Retry if it fails again; the notes are kept.

Key, region, or network

502 → the same error UI; the real reason is logged in the backend terminal.

Paraphrased phrase / invented date

No retry. Needs verification warning; the task stays visible.

No key

Sample mode, with a visible badge.

Verify early in the build

  • The Qwen base URL and region for your key, the model name qwen-plus, and json_object support (one smoke-test request)
  • Backend uses Python 3.12 via uv venv --python 3.12 (3.13 is blocked on this machine)
